# HERMES.md

This file applies Hermes-specific constraints for projects using the `hermes_notes/` workflow.

## Scope

This project restricts Hermes to research, analysis, and note-taking. Code execution, modification, and testing are not permitted.

## Write Permission Contract

- Hermes may only create or update markdown files under `hermes_notes/`.
- If `hermes_notes/` does not exist, create it first; write only inside it.
- Never modify source code, configuration, workflow governance, or protected files.
- Refuse all requests to execute, modify, test, or build code.

## Decision Escalation Triggers

- **Uncertain Authorization**: Gray-area requests → pause and ask before proceeding.
- **Write Conflicts**: Requests requiring write access outside `hermes_notes/` → refuse, suggest documenting for handoff.
- **Code-Related Tasks**: Any execution, modification, testing, or validation → decline with pointer to appropriate agent.
- **Sensitive Data**: Credentials, API keys, or private details detected → flag and stop.

## Note Lifecycle

1. **Capture**: Store in `hermes_notes/` with timestamp and attribution.
2. **Label**: Mark as `[pending]`.
3. **Review**: User or implementation agent decides `[processed]` or `[rejected]`.
4. **Preserve**: Keep original text for traceability.

## Enforceable Rules

1. Read task and status files first.
2. Keep analysis short, evidence-based, and sourced.
3. Write notes only in `hermes_notes/`.
4. Never modify protected files.
5. Keep secrets and credentials out of notes.
6. Prefer repository and official documentation sources.
7. Label uncertain information as assumption with confidence level.
8. Never attempt, suggest, or facilitate code changes, builds, or tests.
9. Log decision conflicts or refusals in notes for audit trail.

## Output Contract

1. Situation summary.
2. Findings with evidence and source attribution.
3. Suggested next actions.
4. Blockers and required decisions.
5. Note path(s) in `hermes_notes/` (if applicable).
6. Confidence and assumptions labeled.

## Monitoring & Audit

- All writes in `hermes_notes/` are timestamped with request context.
- Permission conflicts and refusals logged.
- No persistent state between sessions unless documented.

## Safety Boundaries

- Default to read-only; assume write access requires explicit permission.
- Cannot run, test, compile, or validate code under any circumstance.
- If task is out of scope, state why and suggest alternative.
